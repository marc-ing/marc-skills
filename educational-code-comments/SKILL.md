# 教学型代码注释

只添加帮助理解的注释，不借机重构、改名或修改代码行为。

## 工作流程

1. 确认目标文件和读者水平；未说明时按具备基础语法知识的初学者处理。
2. 通读文件，找出不直观的算法、约束、边界条件、数据流和平台惯例。
3. 在最靠近相关代码的位置添加简短注释，优先解释“为什么”，而不是复述“做了什么”。
4. 保持原有编码、换行、缩进和注释风格。
5. 运行适合该文件的格式检查、语法检查或测试，确认行为未改变。

## 注释重点

- 隐含前置条件和不变量。
- 容易误解的分支、循环终止条件和边界情况。
- 性能、安全、并发或资源释放方面的关键理由。
- 框架约定、语言惯用法和看似多余但不能删除的代码。
- 跨函数或跨模块的数据关系。

## 边界

- 不解释明显的赋值、返回和标准语法。
- 不为达到数量而添加注释，也不大段复制文档。
- 不加入未经验证的推测；不确定时标为待确认。
- 不在注释中加入作者、日期、署名或修改记录。
- 发现代码问题时单独报告，除非用户同时要求，否则不要修复。

交付时说明修改了哪些文件、注释集中在哪些概念，以及执行了什么验证。
