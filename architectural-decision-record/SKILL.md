# 架构决策记录

一次只记录一项决策。这个 Skill 用于整理已有决策，不代替技术调研，也不虚构未讨论的结论。

## 工作流程

1. 查找仓库现有的 ADR 目录、模板和编号规则，已有约定优先。
2. 从上下文提取问题、约束、最终选择、备选方案和后果。
3. 缺少会改变决策含义的关键信息时，最多询问三个问题。
4. 按仓库约定写入新文件；没有约定时使用 docs/adr/NNNN-title-slug.md。
5. 写完后检查事实与推测是否区分、正负后果是否完整、链接是否有效。

## 默认结构

# ADR-NNNN：决策标题

## 状态

Proposed、Accepted、Rejected、Deprecated 或 Superseded。

## 日期

使用 YYYY-MM-DD。

## 背景

说明要解决的问题、当前约束，以及为什么现在需要做决定。

## 决策

明确写出选择了什么，并概括最关键的理由。

## 备选方案

列出真正讨论过的方案及未采用原因。没有材料时写“未记录”，不要编造。

## 后果

分别记录收益、代价、风险和后续工作。

## 相关资料

只列出已知的 issue、文档、原型或其他 ADR。

## 边界

- 不把提议写成已经接受的决定。
- 不虚构参与者、日期、评估数据或备选方案。
- 不覆盖现有 ADR；编号冲突时选择下一个可用编号。
- 不强制加入无关字段，保持文档简短、可维护。

交付时给出文件路径，并指出仍标为“未记录”或待确认的内容。
