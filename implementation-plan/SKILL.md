# 技术实施计划

计划必须建立在当前仓库事实之上。只写计划，不实施改动。

## 工作流程

1. 明确目标、成功标准、范围和明确不做的事项。
2. 检查相关代码、测试、配置和项目约定，引用真实文件路径与符号。
3. 识别依赖关系，将工作拆成顺序清晰、可独立验证的步骤。
4. 为每一步写明改动位置、预期变化和验证方式。
5. 补充风险、迁移或回滚方案，以及仍需用户决定的问题。

## 输出结构

# 计划标题

## 目标与成功标准

说明完成后的可观察结果。

## 范围

分别列出包含项和不包含项。

## 现状

概括相关实现，并引用关键文件。

## 实施步骤

每一步包含：

- 目标
- 涉及文件或模块
- 具体改动
- 依赖的前置步骤
- 验证方法

## 测试与验收

列出自动测试、手工验证和完成条件。

## 风险与回滚

记录兼容性、数据、安全和部署风险。

## 待确认事项

只保留会改变方案的未决问题。

不要编造不存在的文件、接口或约束。无法从仓库确认的内容明确标为假设。
