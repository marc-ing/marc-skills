# 项目 README

README 应帮助新读者快速理解、安装并运行项目。所有命令和功能说明都必须能从仓库中得到验证。

## 工作流程

1. 检查项目入口、依赖清单、配置示例、脚本、测试和现有文档。
2. 判断目标读者以及 README 是新建还是更新；更新时保留仍然准确的内容。
3. 选择项目真正需要的章节，不机械套用完整模板。
4. 验证安装、运行和测试命令，无法执行时至少核对脚本定义。
5. 检查链接、路径、环境变量名称和示例是否与仓库一致。

## 常用结构

- 项目名称与一句话说明
- 主要功能
- 环境要求
- 安装与快速开始
- 基本使用示例
- 配置说明
- 开发与测试
- 项目结构或工作原理，仅在有助理解时加入
- 许可证，仅在仓库确有对应文件时加入

## 写作规则

- 先给最短可运行路径，再补充细节。
- 命令可直接复制，必要时注明执行目录和平台差异。
- 不添加无法验证的徽章、截图、路线图、性能数据或兼容性承诺。
- 不重复其他文档的长篇内容，改用相对链接。
- 不删除用户已有的重要说明，除非它已过时且能被证实。
- 默认使用 GitHub Flavored Markdown，少用装饰和表情。

交付前确认 README 中没有占位符、失效的本地路径或虚构命令。
