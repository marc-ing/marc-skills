# 配图提示词编写

每张图都必须先保存完整最终提示词，再调用图片生成工具。提示词文件既是生成输入，也是复现和修改记录。

## 文件格式

文件路径：`prompts/NN-{type}-{slug}.md`。

```yaml
---
illustration_id: 1
type: infographic
style: sketch-notes
palette: macaron
aspect: "16:9"
language: zh
output: ../01-infographic-example.png
references:
  - filename: ../references/01-ref-example.png
    usage: direct
---

# 任务

生成一张用于文章正文的独立位图插图。

# 内容语境

- 文章主题：……
- 所在章节：……
- 这张图要帮助读者理解：……

# 布局

ZONES:
1. ……
2. ……

# 文字

LABELS:
- “准确标签”
- “42%”

# 颜色

COLORS:
- 背景：……
- 主色：……
- 强调色：……

# 风格

STYLE:
- ……

# 比例

ASPECT: 16:9

# 禁止项

- 不添加未列出的文字、数字、标志、水印或签名。
- 不生成无法辨认的装饰性小字。
- 不改变数据、单位、先后顺序和箭头方向。
```

只有真实存在且需要直接传给模型的图片才写入 `references`。用途为 `style` 或 `palette` 时，把提取结果写进正文，不必传递原图。

## 通用构图要求

- 一个画面只承担一个主要信息任务。
- 主视觉必须在缩略图尺寸下仍可识别。
- 信息按标题、核心关系、次要说明三级组织；不依赖大量小字。
- 元素之间保持清晰间距，避免边缘拥挤和交叉遮挡。
- 箭头只表达明确方向，不把装饰线误用为关系线。
- 比较图的两侧使用一致的维度、尺度和视觉权重。
- 时间线从左到右或从上到下保持单一方向。

## 色彩规则

- 用背景色建立整体气质，用主色承载主体，用强调色标记少量重点。
- 同一语义在同组图片中使用同一颜色。
- 不把警告红、成功绿等带强语义的颜色随意用于装饰。
- 配色必须包含可读性描述，例如“深蓝文字置于浅米色背景”，不能只写“好看的蓝色”。
- 需要精确品牌色时写出色值，并确保用户有权使用。

## 人物与场景

- 人物只保留表达动作、关系和情绪所需的特征。
- 不生成可识别的真实人物，除非用户提供合法参考图并明确要求。
- 不复刻受保护角色；改用原创人物、通用轮廓或符号。
- 场景图仍需服务章节内容，不使用与主题无关的办公桌、灯泡或握手等陈词滥调。

## 图中文字

- `LABELS` 必须逐字列出允许出现的文字。
- 优先控制在 3–8 个短标签；单个标签尽量不超过 10 个汉字。
- 数字、百分比、货币、日期和单位必须与文章一致。
- 引语过长时改为关键词，不把整段文字放进图片。
- 中文提示应明确“使用简体中文”；英文提示应明确大小写。

## 类型模板

### `infographic`

用于把一组事实、指标或概念组织成一眼可读的总览。

```text
LAYOUT:
- 顶部：简短主题标签，可省略大标题
- 中部：3–5 个信息区，每区包含图形、准确数字或关键词
- 底部：关系总结或核心结论，不添加来源之外的内容

READING ORDER:
- 使用清晰的从左到右或从上到下顺序
- 用大小、位置和少量强调色建立层级
```

数据不足时制作概念信息图，不虚构柱状图、百分比或趋势线。

### `scene`

用于叙事、体验、人物行动和情绪转折。

```text
SCENE:
- 环境：具体地点、时间和氛围
- 主体：人物或物体正在做什么
- 关键细节：与章节直接相关的 2–4 个元素
- 情绪：通过姿态、光线和色彩表达，不依赖文字说明
```

避免摆拍式人物、空泛“成功人士”形象和与正文无关的电影化奇观。

### `flowchart`

用于步骤、分支、循环和因果链。

```text
FLOW:
- 起点：……
- 步骤 1：……
- 判断或分支：……
- 步骤 2：……
- 终点或反馈循环：……

CONNECTORS:
- 每条箭头都注明方向
- 不允许交叉歧义
```

节点标签保持平行句式。流程有条件时明确“是/否”或对应条件。

### `comparison`

用于两个或多个对象按相同标准比较。

```text
COLUMNS:
- 左侧对象：……
- 右侧对象：……

ROWS:
1. 比较维度：左侧事实 / 右侧事实
2. 比较维度：左侧事实 / 右侧事实
3. 比较维度：左侧事实 / 右侧事实

BALANCE:
- 两侧面积、字号和信息量相近
- 差异通过内容和有限强调色表达，不用夸张褒贬符号
```

### `framework`

用于模型、架构、层级、环形系统和模块关系。

```text
STRUCTURE:
- 中心或顶层：……
- 模块 A：职责与输入输出
- 模块 B：职责与输入输出
- 模块 C：职责与输入输出
- 模块之间的关系：单向、双向、包含或依赖
```

结构形式必须来自内容：层级用上下布局，循环用环形，输入输出用管线，不能为了视觉效果任意选择。

### `timeline`

用于历史、版本、阶段和里程碑。

```text
TIMELINE:
- 方向：从左到右
- 时间点 1：日期 + 事件
- 时间点 2：日期 + 事件
- 时间点 3：日期 + 事件
- 当前状态或下一阶段：……
```

时间顺序必须核对。日期精度不一致时保持原文精度，不自行补齐月份或日期。

## 参考图写法

直接参考图在提示词中明确：

```text
REFERENCE — MUST USE:
- 保留：主体轮廓、服装特征和主要构图关系
- 可调整：背景、配色和辅助元素
- 不复制：标志、签名、水印和与任务无关的文字
```

只借鉴风格时写成可观察特征，例如“粗细不均的黑色手绘线、低饱和色块、米白纸张纹理”，不要只写“和参考图一样”。

## 生成前检查

- 提示词文件已经落盘。
- 输出文件名与大纲一致。
- 类型、风格、配色和比例完整。
- 所有标签均有内容来源。
- 不存在临时占位符。
- 直接参考图路径存在且后端支持。
- 提示词包含禁止额外文字、水印和签名的要求。
